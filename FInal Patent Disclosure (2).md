## 1) Describe the invention.

**Title**: Trinetra — An Agentic AI Platform for Automated Commercial Credit Underwriting Using Multi-Agent Vector-Memory Architecture

### 1a) Describe the invention in your own words. Is the invention a new process, composition of matter, device or product, system, software, or a combination of these elements?

Trinetra is a **software system** that automates the entire commercial credit underwriting lifecycle — from financial document ingestion to a professional Credit Appraisal Memorandum (CAM) — using a novel multi-agent architecture with shared vector-memory. The system replaces the manual, multi-day process of evaluating corporate loan applications with an automated pipeline that delivers an explainable credit decision in approximately 60 seconds.

The invention comprises the following core technical components:

**1. Multi-Agent Event-Driven Architecture**

The system employs 14 specialized AI agents, each responsible for a distinct domain of credit analysis. Unlike monolithic credit scoring systems, these agents operate independently and communicate through a Redis Streams event bus using a publish-subscribe pattern with consumer groups. Each agent inherits from a common base class (`AgentBase`) that provides:
- Event consumption via Redis Streams with Consumer Group support (XREADGROUP)
- Crash recovery through Pending Entry List (PEL) replay — if an agent crashes mid-processing, upon restart it automatically re-reads and re-processes unacknowledged messages
- Status broadcasting via Redis Pub/Sub for real-time WebSocket updates to the user interface
- Graceful shutdown via POSIX signal handling (SIGTERM, SIGINT)

The 14 agents and their trigger events are: (i) Compliance Agent — triggered by `application_created`; (ii) Document Agent — triggered by `documents_uploaded`; (iii) GST Agent — triggered by `documents_parsed`; (iv) Bank Reconciliation Agent — triggered by `gst_done`; (v) MCA Agent — triggered by `documents_parsed`; (vi) Web Intelligence Agent — triggered by `documents_parsed`; (vii) PAN Verification Agent — triggered by `application_created`; (viii) Model Selector Agent — triggered by `features_ready`; (ix) Risk Agent — triggered by `model_selected`; (x) Bias Agent — triggered by `risk_scored`; (xi) Stress Agent — triggered by `risk_scored`; (xii) Personal Discussion Agent — triggered manually; (xiii) CAM Generator Agent — triggered by `all_agents_done`; (xiv) Monitor Agent — runs continuously.

**2. Shared Vector-Memory via Qdrant Database**

All 14 agents share a common vector database (Qdrant) organized into 14 domain-specific collections. Each collection stores 384-dimensional embedding vectors generated by the `all-MiniLM-L6-v2` Sentence Transformer model with Cosine distance similarity. The collections are: `document_chunks`, `financial_profiles`, `gst_patterns`, `bank_recon_profiles`, `news_articles`, `litigation_records`, `rbi_circulars`, `mca_filings`, `pan_profiles`, `risk_decisions`, `pd_transcripts`, `stress_scenarios`, `audit_events`, and `application_summaries`.

This architecture enables **cross-agent semantic reasoning** — for example, the Risk Agent performs hybrid searches (vector similarity combined with metadata filters) across `financial_profiles`, `gst_patterns`, and `litigation_records` simultaneously to produce a holistic risk score. The CAM Generator Agent reads from all 14 collections to synthesize the final report.

**3. Unified Credit Schema Object (UCSO)**

Every loan application is represented by a single JSON document called the Unified Credit Schema Object (UCSO) with 18 namespaces. Each agent reads the full UCSO, processes its domain, and writes results back to its designated namespace via a RESTful PATCH operation. The namespaces include: `company_info`, `documents`, `compliance`, `financial_summary`, `gst_analysis`, `bank_reconciliation`, `mca_intelligence`, `web_intel`, `pan_verification`, `derived_features`, `decision_confidence`, `risk`, `bias_checks`, `stress_results`, `pd_intelligence`, `cam_output`, `monitoring`, and `metadata`. A JSON Schema validator enforces data integrity at the UCSO client level, preventing malformed data from entering the pipeline.

**4. Text and Document Processing Pipeline**

Financial documents (ITR filings, bank statements, GST returns, audit reports) in PDF format are processed using PyMuPDF and pdfplumber for text extraction. The extracted text is chunked, embedded into 384-dimensional vectors using Sentence Transformers, and stored in the Qdrant `document_chunks` collection. The Document Agent then derives structured financial metrics (DSCR, current ratio, debt-to-equity, EBITDA margin, revenue growth) from the extracted text and stores them in the `financial_profiles` collection.

**5. Tri-Lens Risk Scoring with Attention-Weighted Fusion**

The invention introduces a proprietary risk scoring algorithm called Tri-Lens that evaluates borrowers across three independent lenses: (i) Financial Lens — solvency, liquidity, and growth metrics (base weight: 0.45); (ii) Behavioral Lens — GST compliance, bank cash flows, circular trading indicators, cheque bounce rates (base weight: 0.35); (iii) Contextual Lens — web news sentiment, litigation severity, years in business, CIBIL score, promoter holding (base weight: 0.20). Each lens produces a sub-score and a confidence value. The sub-scores are fused using an attention-weighted mechanism where the final weight of each lens is proportional to both its base weight and its confidence (proportion of available features). The system supports sector-adaptive normalization using industry-specific statistical profiles and employs sigmoid curves for non-linear risk mapping on tail-risk features (leverage, bounce rate, GST discrepancy).

**6. GST Fraud Detection via Temporal Knowledge Graph**

The system implements a Temporal Knowledge Graph (TKG) using the NetworkX library to model supplier-buyer relationships from GST transaction data. The TKG enables: (i) Detection of multi-hop circular trading cycles (A → B → C → A) with temporal constraints using `nx.simple_cycles()` on the directed transaction subgraph; (ii) Promoter network risk propagation with exponential temporal decay — the risk score associated with a director's prior involvement with a fraudulent company decays according to the formula R(t) = R_base × e^(−λ × Δt), where λ = ln(2) / half_life_years and Δt is the elapsed time since the association.

**7. Automated Credit Appraisal Memorandum Generation**

The CAM Generator Agent produces a professional 10-page Credit Appraisal Memorandum in Microsoft Word (.docx) format using a 110-tag template rendered by the `docxtpl` library. The agent retrieves intelligence from all 14 Qdrant collections and all 18 UCSO namespaces. A Large Language Model (Groq `llama-3.3-70b-versatile`) synthesizes qualitative sections such as management assessment and industry outlook. Missing data fields are auto-filled with context-aware realistic values using LLM inference rather than static defaults.

**8. Self-Healing Workflow Orchestrator**

A central Workflow Orchestrator running within the FastAPI backend continuously monitors the pipeline state. It implements a Transactional Outbox pattern — agent events are first written to a database outbox table, then asynchronously relayed to Redis Streams, ensuring no events are lost even if Redis is temporarily unavailable. A state reconciliation loop scans for stuck applications every 30 seconds. If an application has not progressed for more than 3 minutes, the orchestrator identifies the blocked stage and re-publishes the appropriate trigger event to resume the pipeline.

### 1b) Does the invention provide a new use of or an improvement to, an existing product or process?

Yes. The invention provides a fundamental improvement over the existing commercial loan underwriting process:

1. **Manual to Fully Automated**: The current process requires a credit analyst to manually log into multiple government portals (GSTN, MCA21, CIBIL), download reports, input data into spreadsheet models, and produce a Credit Appraisal Memorandum — taking 3 to 5 business days. Trinetra automates this entire pipeline in approximately 60 seconds.

2. **Sequential to Parallel Processing**: In the manual process, verification steps occur sequentially. In Trinetra, 14 agents operate in parallel — compliance checks, document parsing, GST analysis, web intelligence gathering, and MCA verification execute simultaneously once triggered by upstream events.

3. **Subjective to Explainable Decisions**: Traditional credit decisions rely on the subjective judgment of individual analysts. Trinetra replaces this with ML-based risk scoring using SHAP and LIME that provide feature-level attribution for every decision.

4. **Isolated to Cross-Referenced Data**: Existing tools analyze financial data in isolation. Trinetra's vector-memory architecture enables cross-referencing between financial ratios, GST fraud signals, court litigation records, news sentiment, and borrower interview transcripts within a single semantic search space.

5. **Static Rules to Adaptive Intelligence**: Traditional rule-based systems require code changes when regulations change. In Trinetra, compliance rules (RBI circulars, MCA guidelines) are stored as embedded vectors in Qdrant collections that can be updated without modifying application code.

6. **No Fraud Detection to Graph-Based Fraud Detection**: Current underwriting systems do not detect complex fraud patterns like circular trading rings. Trinetra's Temporal Knowledge Graph detects multi-hop circular trading cycles and computes promoter-associated fraud risk with temporal decay.

## 2) From the description, identify and provide a detailed description of specific novel and unusual features.

Trinetra has several features that do not exist in current underwriting systems or have never been combined in this manner:

### 1. Shared Vector-Memory Architecture for Multi-Agent Credit Analysis

Unlike conventional systems that use relational databases where each module reads and writes structured data independently, Trinetra's 14 agents share a set of 14 vector database collections where findings are stored and retrieved as high-dimensional embeddings. This enables semantic similarity searches across heterogeneous data types. For example, the Risk Agent can search for "companies with high GST discrepancy and declining revenue" across `gst_patterns` and `financial_profiles` simultaneously, retrieving semantically similar patterns from past applications. This cross-collection intelligence sharing creates an institutional memory that improves with every processed application. No existing credit underwriting system combines multi-agent coordination with shared vector-memory for semantic reasoning.

### 2. GST Circular Trading Detection via Temporal Knowledge Graph

Standard fraud detection systems compare individual transaction values against fixed thresholds, which cannot detect complex multi-entity fraud schemes. Trinetra constructs a directed graph of all supplier-buyer relationships from GST transaction data and applies cycle detection algorithms (`nx.simple_cycles()`) to identify circular trading loops (e.g., Company A → Company B → Company C → Company A). Additionally, the system computes a promoter risk propagation score using exponential temporal decay: R(t) = R_base × e^(−λ × Δt), where λ = ln(2) / half_life_years. This combined graph-based cycle detection with temporal decay-weighted promoter risk is a novel approach not found in existing credit underwriting systems.

### 3. Tri-Lens Attention-Weighted Risk Scoring with Differential Privacy

The Tri-Lens algorithm is a novel risk scoring method that evaluates borrowers across three independent analytical lenses (Financial, Behavioral, Contextual) and fuses them using a dynamic attention mechanism. Unlike static weighted-average approaches, the attention weights in Tri-Lens adjust dynamically based on the confidence of each lens — defined as the proportion of available features out of the total expected features. If GST data is missing, the Behavioral Lens confidence drops, and the Financial and Contextual lenses automatically receive higher effective weights. The system optionally applies Differential Privacy using the Laplace mechanism (noise scale = sensitivity / epsilon) to the final risk score, enabling secure multi-institutional deployment where individual borrower scores cannot be reverse-engineered.

### 4. Privacy-Preserving Federated Scoring

When data from multiple lending institutions flows through the system, individual borrower details could potentially be traced back. The Tri-Lens scorer supports optional Differential Privacy through a configurable epsilon parameter. When enabled, calibrated Laplace noise is added to the final risk score, ensuring that the output cannot be used to infer the exact input features of any individual borrower. This allows multiple banks to share a common risk-scoring infrastructure without exposing proprietary customer data.

### 5. Anti-Hallucination Consistency Engine for AI-Generated Credit Appraisals

Existing LLM-based report generators often hallucinate missing financial data to fulfill templated requirements, producing confident but mathematically impossible outputs. Trinetra introduces an Anti-Hallucination Consistency Engine that intercepts AI-generated data before document rendering. It performs deterministic cross-validation: recomputing the Interest Coverage Ratio (ICR) from EBITDA and Interest Expense, verifying EBITDA margins against Revenue, computing exact Bank vs. GST turnover divergence, and cross-referencing Aadhaar linkage flags against masked output requirements. If the AI-generated or extracted values violate these deterministic relationships, the engine automatically corrects the outputs or forces a "Data pending" failure state. This strictly enforces zero mathematical drift between the raw Unified Credit Schema Object (UCSO) and the final rendered Credit Appraisal Memorandum.

### 6. Unified Searchable Space for Structured and Unstructured Data

Most credit scoring tools operate exclusively on structured numeric data (financial ratios, transaction amounts). Trinetra embeds all data types — structured financial metrics, unstructured news articles, legal filings, RBI regulatory circulars, borrower interview transcripts — into the same 384-dimensional vector space. This allows a single semantic query like "high leverage with negative media coverage and ongoing litigation" to retrieve relevant results spanning across financial profiles, news articles, and litigation records simultaneously, using Qdrant's hybrid search (vector similarity + metadata key-value filters).

### 6. Automatic Best-Model Selection with Cross-Validation

Rather than locking credit decisions to a single fixed ML model, the Model Selector Agent trains three models in parallel — XGBoost, LightGBM, and Logistic Regression — on the same dataset for every application batch. It evaluates each model using AUC-ROC on a holdout validation set and automatically selects the best-performing model for inference. This ensures the system adapts to different borrower populations and economic conditions without manual model retraining or reconfiguration.

### 7. Built-In Counterfactual Fairness Testing on Every Decision

Instead of performing bias audits periodically, the Bias Agent runs a counterfactual fairness test on every single credit decision. For each of the top 3 SHAP-ranked risk features, the agent replaces the feature value with its population median and recomputes the risk score. If the decision flips (e.g., REJECT → APPROVE), that feature is flagged as "overweighted" and the decision is flagged for human review. This per-decision fairness check is novel in the credit underwriting domain where bias audits are typically performed retroactively on batches.

### 8. Self-Healing Pipeline with Crash Recovery and Automatic Reconciliation

The system uses Redis Streams Consumer Groups with Pending Entry List (PEL) management for crash recovery. If an agent crashes during processing, the message remains unacknowledged in the PEL. When the agent restarts, it first reads pending messages (using ID `0`) before consuming new messages (using ID `>`), guaranteeing exactly-once processing without message loss. Additionally, a central Workflow Orchestrator scans for stuck applications every 30 seconds and automatically re-triggers the appropriate pipeline stage, making the system self-healing without manual intervention.

## 3) How does the invention differ from present technology? What problems does it solve, or what advantages does it possess?

There are two categories of existing technology that address parts of the same problem:

**Category 1: OCR and Document Digitization Software**

Existing OCR tools (ABBYY, Nanonets, Google Document AI) convert text from financial documents into digital form but do not analyze the content. They produce raw text or structured fields but cannot derive financial ratios, detect fraud patterns, or produce risk assessments.

**Category 2: Rule-Based Scoring Engines**

Banks currently employ rule-based scoring engines that analyze structured numeric data using predetermined formulas. Their fundamental limitation is the inability to process unstructured data and the inability to detect complex multi-entity fraud patterns that require graph analysis.

**How Trinetra Differs:**

Unlike both categories, Trinetra combines document processing, semantic analysis, graph-based fraud detection, ML-based risk scoring with explainability, fairness auditing, and automated report generation within a single integrated platform:

1. **Vector-memory reasoning**: All 14 agents read from and write to shared Qdrant vector collections, enabling semantic cross-referencing between heterogeneous data sources that no rule-based or OCR system can perform.
2. **Graph-based fraud detection**: The Temporal Knowledge Graph detects circular trading cycles and promoter-linked fraud risks — capabilities absent in all existing rule-based scoring engines.
3. **Explainable AI**: Every risk decision includes SHAP feature attributions showing exactly which factors contributed and by how much.
4. **Adaptive model selection**: The system automatically evaluates and selects the best ML model for each application batch.
5. **End-to-end automation**: From raw PDF upload to a professional 10-page CAM report, the entire underwriting pipeline is automated.

**Advantages:**

- Processes both structured and unstructured data within a unified semantic space.
- Detects complex multi-entity fraud schemes invisible to rule-based systems.
- Provides explainable, auditable decisions with feature-level attribution.
- Reduces underwriting time from 3–5 business days to approximately 60 seconds.
- Adapts to changing regulations without code modifications.

## 5) Characterize the disadvantages and limitations of the invention.

### 1. Dependency on OCR Extraction Quality
All financial figures are extracted from PDF documents through OCR. Poor quality scans or handwritten documents can produce incorrect extractions. **Mitigation**: The Document Agent computes a confidence score for each extracted field. Fields with confidence below a configurable threshold are flagged for manual review. Future versions will implement dual-extraction verification using a secondary OCR engine.

### 2. Operational Complexity of Multi-Agent System
Running 14 independent agents through an event-driven distributed system is more complex to operate than a monolithic application. **Mitigation**: The Monitor Agent tracks pipeline health through heartbeat events. The Workflow Orchestrator's state reconciliation loop automatically detects and re-triggers stuck pipeline stages every 30 seconds. Distributed trace IDs propagate through all agent interactions for end-to-end request tracing.

### 3. Dependency on External Government Portals
Several agents pull data from government portals (MCA21, GSTN, SurePass API) which the system cannot control. **Mitigation**: Each agent implements graceful degradation — if the external API call fails, the agent records the failure and allows downstream agents to proceed with available data. The Workflow Orchestrator can retry failed stages when the external service recovers.

### 4. Model Accuracy Variation Across Sectors
The ML models are trained on historical data and may be less accurate for underrepresented sectors. **Mitigation**: The Model Selector Agent performs per-batch cross-validation and selects the best model dynamically. The Tri-Lens algorithm uses sector-adaptive normalization with industry-specific statistical profiles.

### 5. LLM Dependency for Qualitative Sections
The CAM Generator Agent uses a Large Language Model to synthesize qualitative report sections. LLM outputs can occasionally contain inconsistencies. **Mitigation**: The LLM is used solely for synthesizing narratives from verified structured data. All quantitative fields are computed deterministically by the respective agents and are not LLM-generated.

**Claim 2**: A system for automated credit underwriting comprising: a vector database organized into domain-specific collections; an event-driven message bus with consumer group support and crash recovery via pending entry list replay; a plurality of specialized AI agents subscribing to trigger events and writing to designated namespaces; a workflow orchestrator with transactional outbox relay and automatic state reconciliation; and a report generator retrieving intelligence from all collections.

**Claim 3**: A method for detecting circular trading fraud comprising: constructing a directed graph from transaction records; applying cycle detection algorithms to identify circular loops; computing promoter risk propagation using exponential temporal decay R(t) = R_base × e^(−λ × Δt); and storing results as embedding vectors for cross-referencing.

**Claim 4**: A method for multi-dimensional credit risk scoring comprising: evaluating a borrower across three independent lenses (Financial, Behavioral, Contextual); computing confidence for each lens based on available features; applying attention-weighted fusion; optionally applying differential privacy via Laplace mechanism; and providing per-decision explainability through SHAP attribution.
